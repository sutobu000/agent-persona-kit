# セッション冒頭の状況確認

**目的は「相手に説明させないこと」。** 相手が文脈を思い出して入力する手間を、こちらが先に消す。

読み取りだけを行う。この手順の中で変更を加えない。

記憶の正本: `{{MEMORY_TOOL}}`

## 手順

1. **記憶の範囲を確認する** — `README.md`の`scope`が今回の作業範囲と一致する場合だけ、以降の記憶ファイルを読む。一致しなければ記憶を混ぜない。
2. **プロフィールを読む** — `profile.md`の確認済み事項だけを使う。未確認事項を推測で埋めない。
3. **申し送りを読む** — `handover.md`にある面をまたいだ横断的な引き継ぎ。直近{{HANDOVER_CAP}}件で流れるので、まずここ。
4. **進行中のプロジェクトノートを見る** — `projects/index.md`で`status`が動いているものを選び、冒頭の「現況」「次の一手」を読む。
5. **定期情報収集の当日分を読む** — {{REVIEW_DAY}}以外の日は当日分だけでよい(`tech-watch` skill が書いている場合)。
6. **作業環境の状態を確認する** — 現在のリポジトリの同期状態(未コミットの変更・リモートとの差)。
7. **境界を確認する** — 今回触る予定の場所が {{RESOURCE_RULES}} の許可範囲内か。

## 報告の形

**全件を読ませない。** 相手が今すぐ知るべきことだけを絞って出す。

- 前回からの続き: 1〜3行
- 進行中の作業と、それぞれの「次の一手」: 各1行
- 相手の判断が要るもの: あれば先頭に。無ければ「無し」と書く
- 環境の異常: あれば。無ければ書かない

その上で、**次に着手する作業を1つ提案してそのまま続行する。**「どうしますか」で終わらせない。

## 注意

- 「要注意」「ブロック中」の印が付いた項目は、短くても必ず触れる。
- 記録は書かれた時点の事実。**名指しされたファイル・設定が今も存在するかは、使う前に確認する。**
- 到達できなかった情報源は「0件」ではなく「到達できなかった」と報告する。
